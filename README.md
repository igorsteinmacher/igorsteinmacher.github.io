# igor.pro.br

Plain HTML site on GitHub Pages. Lists live in `data/*.toml`; scripts fill them
into the pages and generate the CV. Python 3.11+ standard library only — nothing
to install (Chrome is used to print the CV PDF).

## How do I update…

| What | Edit | Then |
|---|---|---|
| Students (`people.html`; current on the home page too; the "supervised N PhD students" count follows the alumni list) | `data/students.toml` | `python3 scripts/build_site.py` |
| Research themes and their representative papers | `data/research.toml` | `python3 scripts/build_site.py` |
| Funded projects / grants | `data/projects.toml` | `python3 scripts/build_site.py` |
| Awards & honors (`activities.html`; newest 3 on the home page) | `data/honors.toml` | `python3 scripts/build_site.py` |
| Paper awards (★ badges + Awards list) | `data/awards.toml` | `python3 scripts/build_pubs.py` |
| Courses | `data/teaching.toml` | `python3 scripts/build_site.py` |
| Keynotes, talks & panels (`activities.html`; first 2 on the home page) | `data/talks.toml` | `python3 scripts/build_site.py` |
| Software / tools | `data/software.toml` | `python3 scripts/build_site.py` |
| Service & leadership (`activities.html`) | `data/service.toml` | `python3 scripts/build_site.py` |
| CV-only content (education, experience, highlights, detailed service) | `data/cv.toml` | `python3 scripts/build_cv.py --pdf` |
| Top navigation (all pages) | `data/site.toml` | `python3 scripts/build_site.py` |
| Publications | nothing — pulled from DBLP monthly | or run `python3 scripts/build_pubs.py` |
| Paper PDFs | drop into `publications/` (see below) | `python3 scripts/build_pubs.py` |
| About / teaching text; prospective-students text | `index.html`; `people.html` directly | — |

Skipping the "Then" step is fine: pushing a change under `data/` triggers
GitHub Actions that rebuild the pages, so you can also edit the TOML files
straight from the GitHub web editor.

## The CV

`scripts/build_cv.py` generates the CV from the same data plus DBLP:
`cv/CV.md` (readable diff), `cv/index.html` (igor.pro.br/cv/) and
`Steinmacher_CV.pdf`.

You approve every change: the **Update CV** Action runs after any `data/`
change and after the monthly DBLP refresh, and when the CV's content changed
it opens (or updates) a pull request titled "CV update". Read `cv/CV.md` under
*Files changed*; merge to publish, close to reject.

To preview locally without touching the repo:

```bash
python3 scripts/build_cv.py --out /tmp/cv --pdf /tmp/cv/CV.pdf
```

## Papers without an open version

`missing_preprints.md` (regenerated by `build_pubs.py`) lists papers that are
neither open access nor on arXiv, each with the exact file name to use. Drop
the accepted-manuscript PDF into `publications/` under that name (or post it to
arXiv) and the next run links it.

## Automation (`.github/workflows/`)

| Workflow | When | Does |
|---|---|---|
| Build pages from data/ | push to `data/` | rebuilds the HTML, commits it |
| Update publications from DBLP | monthly, or when `data/awards.toml` changes | rebuilds `publications.html` |
| Update CV | after either of the above | opens a "CV update" pull request if the CV changed |
| Check links | monthly | opens a "Broken links" issue if any link is broken |

## How it works

Generated parts of each page are wrapped in marker comments:

```html
<!-- BEGIN:students-current (generated from data/students.toml — edit there) -->
...replaced on every build...
<!-- END:students-current -->
```

Edit anything outside the markers by hand; anything inside is overwritten.
`build_site.py` reports a clear error for a missing required field or a
misspelled field name.

Fonts (Space Grotesk, Source Serif 4, JetBrains Mono) are self-hosted in
`fonts/` under the SIL Open Font License.
